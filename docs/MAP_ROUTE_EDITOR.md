# 地图路线编辑（1.4.5）

## 入口与模式

主页面路线卡片 → **地图绘制 · 道路 / 操场**。实时跑步与历史补跑共用当前选中路线。运行和暂停期间不允许应用其他路线。

主页面的“当前使用的路线”显示条打开已有路线列表，顶部“使用默认路线”和“导入 KML 并保存”左右等宽排列。默认路线“大连理工大学盘锦校区路线”与自建路线使用相同卡片布局，显示 400.04 米 / 191 点和内置标记，可点击使用，不提供删除。导入 KML 时先读取并校验，再输入名称保存；地图绘制保存的路线也进入此列表。自建路线支持选择、重命名和移除，移除条目不会破坏已应用路线的快照。

平板主页面左右各自使用 ScrollView，在一侧滚动不会带动另一侧；底部主操作固定。手机保持单列滚动。

| 模式 | 操作 | 生成方式 |
| --- | --- | --- |
| 沿道路 | 点选或拖动画线，松手后规划；选择终点后切换该段手绘 | 画线先提取控制点，再用 Valhalla `pedestrian` 规划；逐段缓存 |
| 操场 | 点击放中心，拖中/长/宽手柄，设置跑道参数、起点和方向 | 本地两直道加两半圆，局部米制坐标生成后转 WGS84，约 2 米采样并精确闭合 |
| 手动 | 点选连线或直接拖动画轨迹；可开平滑、闭合 | 自由笔画先按屏幕精度简化为控制点，再保留折线或使用向心 Catmull–Rom 平滑 |

“更多”中提供新建、从当前路线编辑、输入经纬度跳转、选点列表、服务设置及操作说明。从当前路线编辑时按约 1 米容差提取控制点，过于复杂的路线提示新建，不截断采样点冒充完整编辑。

道路与手动首次进入从空白开始，不把当前默认跑道或旧草稿自动放入地图。当前会话各模式独立保留编辑内容；需要上次草稿时显式选择“更多 → 恢复上次草稿”。仅移动地图或搜索位置，不会覆盖磁盘中未恢复的旧草稿。

## 大地图布局与自由绘制

- 宽度至少 800 dp 时，模式切换位于顶栏，状态、编辑方式、操作及保存位于 224 dp 右侧工具栏。1920×1080 / 240 dpi 的蓝叠中，地图从原先约 1920×594 扩大为 1584×966，可用面积约增加 34%。
- 手机底部保留“点选 / 画线 / 移动”、工具开关及保存；更多工具默认收起，状态与短提示浮于地图底部。
- 点选圆点普通半径由 12 dp 缩为 6 dp，选中半径由 15 dp 缩为 8 dp；命中半径仍为 26 dp。控制点较多时仅显示选中点编号，避免标签堆叠。
- “画线”支持单指及鼠标拖动，拖动期间即时显示笔迹，松手后提交完整一笔，可逐笔撤销。轨迹已有终点时，从终点附近接续；离得太远会提示，不静默补一条长直线。
- 1.4.5 将“重做”改为“清空”，移除“删除选点”。清空只移除当前模式的草稿几何，可撤销恢复；保留视野及参数，不删除已保存路线。操场清空后保持为空，点击地图或应用跑道参数可重新放置。清空后绘制并保存会创建新路线，不覆盖原保存条目。
- 双指介入会取消尚未完成的一笔，把触摸交给原生地图移动/缩放；“移动”模式的单指拖图及点击均不新增坐标。
- 每笔最多采集 10,000 个原始位置，按约 2 dp 的屏幕精度简化；道路模式允许在有限误差内进一步提取拐点。超出道路 20 点或手动 500 点上限会提示调整，不截断笔画末尾。
- 自由绘制保留手动模式当前平滑开关，用户可按需要开启平滑；道路模式会调用步行路网服务，不以手动画线代替规划成功。

已有闭合路线符合跑道形状时，首次进入操场模式会拟合其中心、长轴朝向、半径和直道；不会把路线起点当作操场中心。新建地点没有可用闭合路线时，才在当前视野放置待校准模板。原始 DUTPJ KML 保留原始几何，默认路线不会被测试模板自动覆盖。

400 米模板的中心线半径为 36.8 米，一段直道约 84.3894 米。解析长度为 400 米，最终离散折线约 399.97 米；页面始终显示 `RunRoute` 的实际计算长度。外道按照设定道宽增加弯道半径，不把所有道次都标为 400 米。模板与地图需由用户校准，并非自动识别或现场实测。

手动平滑没有路网、障碍物或跑道边界约束，应检查是否跨越建筑、草地或自交。道路模式不额外做自由样条平滑。

## 默认服务与配置

- 地图组件固定为 `org.maplibre.gl:android-sdk:12.3.1`，使用 TextureView，便于模拟器及原生控件叠加。
- 主页面路线卡片与全屏编辑页都使用真实地图组件；主页面手机预览扩大为整卡宽度，不再保留模拟街区 Canvas。
- 默认地图样式：`https://tiles.openfreemap.org/styles/liberty`。
- 地图样式失败或 18 秒内未就绪时切换 OSM 栅格底图，保留提示与署名；输入 `osm` 可主动使用该底图。
- 默认步行接口：`https://valhalla1.openstreetmap.de/route`。这是公共测试依赖，不提供稳定性保证；用户量增加时替换为适合用途的托管或自建服务。
- 默认地点搜索：`https://photon.komoot.io/api/`。顶栏“搜索”输入地点或地址后显式查询，展示名称/地址，选中后跳转视野。支持兼容 Photon 或 Nominatim 的 HTTPS 服务地址；后者一般为 `/search`。查询关键词发送给所选搜索服务，不发送 Keep 账号信息。
- 搜索不做自动补全；至少间隔约 1.1 秒，结果缓存七天，显示 OSM 数据署名。公共搜索服务用于适量交互查询，不保证特定区域全部地点都能检索到。
- 设置入口：“更多 → 地图与路线服务”。自定义 Valhalla 服务须兼容 `pedestrian`、标准 `/route?json=...` 及默认 polyline6 结果。地图样式输入 HTTPS Style JSON URL；不支持把普通瓦片 URL 当成样式 URL。
- 客户端路线调用至少间隔约 1.1 秒，单线程请求，设置连接/读取超时；拖动结束才重算。取消和版本号共同避免旧响应覆盖新编辑。
- 道路锚点会发送给选定的路线服务；地图服务获得地图请求。应用不向这些服务发送 Keep 认证或账号信息。
- 原生 HTTP 缓存由 SDK 管理，不提供公共 OSM 批量下载或离线预取。

当底图不可用时，轨迹和控制点仍可显示与调整，背景不代表真实街区。操场与手动几何可以离线生成；没有缓存的道路段需要联网规划。设备网络不等同于开发电脑网络，电脑接口请求成功不能证明模拟器底图可达。

道路点吸附与用户选点保留区分：最大偏移超过 20 米提示，超过 200 米不允许应用。相邻道路段有超过 3 米的断口时阻止保存，要求调整衔接点或显式设置相邻手绘段。手绘段连接邻接道路的吸附端点；闭合道路也必须完成回程规划。

## 文件与坐标

应用内部文件目录：

| 文件 | 内容与作用 |
| --- | --- |
| `route-selection.json` | 当前路线的原子提交记录：版本、名称、WGS84 坐标和可选编辑草稿；页面与后台服务统一读取 |
| `selected-route.kml` | 兼容路线镜像；旧安装无 JSON 时仍可读此文件 |
| `route-editor-draft.json` | 尚未应用或最后编辑的草稿、道路几何缓存和地图视野；自动保存，不影响当前路线 |

路线选择 JSON 是权威文件。保存先完成几何与 KML 大小校验，再原子发布选择记录；KML 镜像失败不会让已提交的选择被误报为失败。旧 KML 导入与默认路线恢复也经过同一仓库。权威 JSON 损坏时显示读取失败，不静默改用另一条路线。

草稿自动保存、返回保存与“保存并应用”相互区分；退出草稿不会更换当前路线。道路/手动首次进入不自动恢复旧轨迹；旋转重建保留当前编辑，旧草稿可主动恢复。

`routes/<UUID>.json` 保存命名路线与可选编辑参数；当前选择记录带 `routeId` 关联。首次引入列表时保留已有自定义选择；切到默认路线不会删除命名路线。旧的 `DUTPJ 操场路线` 名称在读取时迁移为新名称，不改变坐标。

地图、草稿、路线与 GPX 都使用 WGS84，GeoJSON 风格数组使用 `[longitude, latitude]`；Android 点对象使用 `latitude, longitude`。现有 Keep 转换仍在其交接边界进行。地图服务设置仅支持与此坐标约定兼容的底图及 Valhalla，不自动接入 GCJ-02 地图数据。

最终路线保留现有 50,000 点、KML 4 MB 等限制；道路最多 20 个控制点，手动最多 500 个控制点。原有开放路线折返、闭合路线循环及历史距离/配速规则继续适用。

## 开发验证

```powershell
$env:JAVA_HOME = 'D:\Dev\Java\jdk-21'
$env:PATH = "$env:JAVA_HOME\bin;$env:PATH"
.\gradlew.bat :app:exportDebugApk :app:testDebugUnitTest :app:lintDebug
```

常规调试包路径：`app/build/outputs/apk/kegent/kegent.apk`。调试版本 `1.4.5-dev`；正式更新包为 `app/build/outputs/updates/kegent-1.4.5.apk`，应用 ID `com.haven.kegent`，versionCode 12。

纯 Java 测试覆盖：不同纬度、方向、起点的跑道长度及闭合，外道增量，手动插值端点，草稿参数往返，保存权威文件与镜像，旧 KML 兼容，未完成道路与断口禁止应用，修改锚点导致缓存失效，以及 Valhalla polyline6 的解码和失败响应。

1.4.1 新增笔画简化、端点保留、道路控制点预算、过短笔画拒绝、闭合保留和不截断超限笔画的单测；蓝叠横屏与模拟手机竖屏分别验证自由绘制、撤销重做、移动不加点、双指不提交额外笔画及保存。截图与测试输出位于 `app/build/reports/map-editor-1.4.1/`。

1.4.2 将路线/控制点投影合并为批量原生调用，按动画帧合并相机重绘并复用路径、坐标数组；自由笔画在松手时批量转换坐标，移动期间直接显示屏幕笔迹。几何未修改时复用路线计算结果，拖点期间合并短时间内的更新，并关闭地图瓦片预取。性能改动以触摸/保存回归和实际使用反馈验证，不承诺所有设备固定帧率。

2026-11-10 的独立蓝叠测试包验证了真实底图显示、原始 DUTPJ 默认路线、操场初始拟合与参数修改、保存后返回/重开、连续三点手动平滑与保存。默认 DUTPJ 原始路线为 400.04 米 / 191 点；基于其几何拟合的可编辑跑道约 400.29 米，两者不混同为同一条坐标数组。截图和测试输出位于 `app/build/reports/map-editor/`。早期 407.64 米测试模板截图使用了错误的初始化中心及未校准朝向，已修正；该截图不能作为默认路线对齐的证据。

`RouteEditorSmokeTest` 仅在应用 ID 以 `.maptest` 结尾的独立测试包运行；普通安装中会跳过，避免修改用户的路线和草稿。可通过本机临时 Gradle init 文件设置独立 `applicationId` 和 `testApplicationId`，构建安装后，仅运行此测试类。不要用完整 `connectedDebugAndroidTest` 流程覆盖已有用户安装；项目既有的某些测试仍要求显式授权并可能卸载应用。

本需求的交付验收是地图编辑、路线保存及现有路线消费的一致性。真实地点的步行路径质量、设备在线底图显示、现场跑道贴合、长期服务可用性和用户偏好仍需要实际使用反馈。
