# Keep 历史记录接入

当前适配范围：本机已登录的 Keep **8.7.30 / versionCode 49337**，设备已提供 Root，并具有 Android `sqlite3`、`stat`、`restorecon` 等命令。普通未 Root 真机可使用历史预览和 GPX 导出，但不能写入 Keep 的私有待同步区。

用户一次配置一条记录：过去的起止时间、KML 路线、配速、步频和体重。距离由有效时长和配速计算；体重仅用于估算热量。开放路线往返，闭合路线循环；所有轨迹点保持绝对与相对时间一致，长记录会控制采样点数。生成的轨迹不冒充导入的原始传感器数据。

流程：

1. 预览时间、距离、配速和采样点数。
2. 检查本机 Keep 的版本、当前账号及摘要表字段。只取账号标识，不保存登录令牌或密码。
3. 用户确认“加入并打开 Keep”后，重新检查账号和正在进行的运动。正在运动时拒绝写入。
4. 关闭 Keep，备份 SQLite 索引；先完成详情文件并设置其属主/权限，再以 SQLite 事务加入摘要。
5. 直接打开 Keep 的运动数据同步页，由用户在待上传列表中核对并使用 Keep 自己的认证和同步逻辑。kgent 显示的是本地交接结果，不把它标作云端上传成功。

本地目录为 `files/local_logs/local_log_<logId>_v2` 和 `databases/summary_log_database.db`，属于 Keep 私有目录。记录 ID 使用当前账号、反向结束时间和已观察到的跑步后缀 `rn`。插入操作拒绝覆盖同 ID 记录、拒绝与本地未同步跑步时间重叠，并保留 kgent 交接回执以防重复点击。云端已有记录的重叠、时效与真实性校验仍由 Keep 决定。

备份和准备记录位于 kgent 私有目录 `files/keep-handoffs/`。它们被排除在 Android 云备份和设备迁移之外。失败时不会覆盖已有记录；可以在应用内继续编辑，或导出 GPX 保存。

维护代价：这是针对具体客户端版本的私有存储适配，不是 Keep 公共 API。Keep 升级后须重新核对模型、字段、记录 ID 和同步行为；适配器会拒绝未知版本。没有修改 Keep APK、规避登录或实现自己的认证签名。

验证分为纯 JVM 路线/时间/序列化测试、Android SQLite schema 测试，以及显式选择运行的本地交接测试。后者要求宿主同时隔离 Keep 的 IPv4/IPv6 网络，并在测试后清除唯一测试记录及恢复隔离规则；普通测试命令会跳过这一条。任何云端成绩写入都不是本地测试通过的含义。
